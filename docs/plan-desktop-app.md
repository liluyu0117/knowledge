# 桌面端改造方案（待批准）

> 分支：`feature/desktop-app`（从 `main@ee64b13` 切出）
> 状态：**方案评审中，未开始改造**
> 原则：后端只加「可配置」开关，不引入桌面耦合；现有 Web 形态继续可用，两条路径共用一份后端。

---

## 1. 目标

把现在「浏览器访问 http://localhost:39217」的形态，变成**双击即用的 Windows 桌面应用**：

- 双击图标 → 出现独立窗口（不是浏览器标签页）→ 直接可用
- 自带 Java 运行时，用户机器不需要装 JDK / Maven
- 关窗即退出（或最小化到托盘），后台服务随之启停，不留孤儿进程
- 数据在本机，可换机迁移

**不在本次范围**：移动端、原生重写界面、多用户/多租户、Linux/macOS 打包。

---

## 2. 现状（改造起点）

| 项 | 现状 |
|---|---|
| 后端 | Spring Boot 3.4.2，fat jar **107MB**，端口 `39217` |
| 前端 | Vue 3 + Vite，构建产物打进 jar 的 `static/`，浏览器访问 |
| 运行时 | 便携 JDK 17（**355MB**，可用 jlink 裁到 ~70MB） |
| 数据 | `D:\KnowledgeBase\.kb`（1.4G，其中 kbdata 1.3G），目录由 `AppPaths` 向上探测 `.kb` 决定 |
| 启动 | `启动知识库.bat` → `mvn spring-boot:run`（需 JDK+Maven，慢） |
| 依赖 | 需要联网（LLM / 向量化），本地索引、会话、备份均在本地 |

**关键约束**：`AppPaths.detectRoot()` 靠「工作目录向上找 `.kb`」定位数据。打包成 exe 后工作目录变成安装目录，必须在改造中做成**可配置**，否则会新建空库、看起来像数据丢失。

---

## 3. 形态选型

| 方案 | 产物 | 体积 | 体验 | 成本 | 依赖 |
|---|---|---|---|---|---|
| **A. 绿色版**（jpackage 自带 JRE） | 文件夹 + `知识库.exe` | ~180MB | 双击启动，**仍开浏览器** | 0.5 天 | 无 |
| **B. 桌面外壳**（Tauri / Electron） | 安装包 exe | Tauri ~120MB / Electron ~260MB | 独立窗口、托盘、无地址栏 | 1.5~2 天 | Tauri 需 Rust；Electron 用现成 Node |
| C. 原生重写前端 | — | — | 最原生 | 2 周+ | 不现实，放弃 |

**推荐 B**，理由：A 只是「省掉装 Java」，本质还是浏览器，不符合「桌面应用」的诉求；C 代价过大。B 里再二选一：

- **B1 Tauri 2**：Rust 壳 + 系统 WebView2（本机已装 156.x），产物小、内存低；**但本机未装 Rust**（rustup + MSVC Build Tools 约 2GB，需联网）
- **B2 Electron**：Node 22 已就绪，零额外工具链，1 天可出可用版本；代价是体积大、内存高

> 结论：**若允许安装 Rust 工具链 → B1（推荐长期）；若想今天就看到成品 → B2，后续再迁 Tauri**（前端代码两者通用，只换壳）。

## 4. 选定架构（以 B1 为例，B2 结构等价）

```
┌─────────────────────────────────────────────┐
│ 桌面壳（Tauri/Electron，单实例）              │
│  ├─ 启动 sidecar：jre\bin\javaw -jar kb.jar │
│  │     -Dkb.home=%APPDATA%\KnowledgeBase    │
│  │     --server.port=<动态空闲端口>          │
│  │     --kb.quiet（不自动开浏览器）           │
│  ├─ 轮询 /api/health 直到 200（≤15s）        │
│  ├─ 创建窗口 → http://127.0.0.1:<port>      │
│  ├─ 托盘：显示/隐藏、退出（退出时 kill 子进程）│
│  └─ 崩溃监听：子进程退出 → 自动重启（限 3 次） │
└─────────────────────────────────────────────┘
              │ HTTP / SSE（本机回环）
┌─────────────▼───────────────────────────────┐
│ Spring Boot（现有代码，仅加 3 个开关）        │
│  数据目录可配 / 端口可配 / 静默模式            │
└─────────────────────────────────────────────┘
```

**前端不做重写**：仍是现有 Vue SPA，由 Spring Boot 提供；壳只是把它装进窗口。

## 5. 改造清单

### 5.1 后端（约 80 行，全部向后兼容）

| 改动 | 说明 |
|---|---|
| `AppPaths` 支持显式数据目录 | 优先级：`-Dkb.home` → 环境变量 `KB_HOME` → 程序目录/当前目录的 `kb-home.txt` → 旧的上溯探测 → `%APPDATA%\KnowledgeBase` |
| `KbServerApplication` 单实例 | 端口上已有本应用响应（`/api/health`）则只激活已有窗口，不重复启动 |
| `--kb.quiet` | 桌面壳内启动时不再调用 `Desktop.browse` 打开浏览器 |
| `/api/health` | 新增极简健康端点（壳用来判断「服务已就绪」），返回版本号与数据目录 |
| 仅监听回环 | `server.address=127.0.0.1`，避免局域网暴露 |
| 优雅退出 | 已有 Spring 生命周期；补 `Runtime.addShutdownHook` 确保 SQLite/Lucene 正常关闭 |

### 5.2 前端（约 30 行）

| 改动 | 说明 |
|---|---|
| 桌面壳标识 | 壳注入 `window.__DESKTOP__=true`（或 Tauri 全局对象），用于隐藏浏览器专属提示 |
| 外链处理 | `target=_blank` 的链接改走系统默认浏览器打开（壳提供 API），避免在应用窗口内漂走 |
| 标题栏 | 首版用系统标题栏（零成本）；二期可换自绘标题栏（含最小化/关闭按钮） |
| 离线提示 | 壳内检测 sidecar 断开 → 顶部条提示「服务已断开，正在重启…」 |

### 5.3 壳工程（新增目录，不影响现有构建）

```
desktop/                     # 新增，独立工程
├─ tauri.conf.json           # 窗口、托盘、单实例、sidecar 配置
├─ src-tauri/…               # Rust 侧：启动/健康检查/托盘/退出
├─ icons/                    # 图标（从 web 图标生成 ico）
└─ scripts/
   ├─ build-runtime.ps1      # jlink 裁剪 JRE（java.se + jdk.unsupported + jdk.crypto.ec + jdk.charsets + jdk.zipfs + jdk.localedata）
   └─ build-desktop.ps1      # 一键：web 构建 → jar 打包 → jlink → 壳打包 → 输出安装包
```

### 5.4 数据与迁移

- 默认数据目录：`%APPDATA%\KnowledgeBase\.kb`
- 首次启动：若检测到旧目录（`D:\KnowledgeBase\.kb` 或 `kb-home.txt` 指定）→ 询问「迁移 / 继续使用原位置」，**默认复制而非移动**，复制前自动打一份 zip 备份
- 迁移后校验：会话数、笔记数、知识库数、索引 chunk 数四项比对

### 5.5 打包与体积预算

| 组成 | 体积 |
|---|---|
| Spring Boot jar | 107MB |
| jlink 精简 JRE | ~70MB |
| 壳（Tauri / Electron） | ~10MB / ~150MB |
| **合计（Tauri）** | **≈190MB**，安装包压缩后 ~130MB |

## 6. 阶段计划与验收

| 阶段 | 内容 | 验收标准 | 估时 |
|---|---|---|---|
| **P0** | 后端三个开关 + `/api/health` + 单实例 | `java -Dkb.home=E:\test -jar kb.jar --kb.quiet` 启动后数据落在 `E:\test\.kb`，不弹浏览器；重复启动只有一个实例 | 0.5d |
| **P1** | 壳工程 + 生命周期 | 双击壳 → 窗口出现并可问答；关窗后 java 进程消失；端口被占用时自动换端口仍可用 | 1d |

| **P3** | 体验完善 | 托盘最小化/恢复、开机自启（可选）、崩溃自动重启、外链走系统浏览器 | 0.5d |
| **P4** | 数据迁移与回归 | 迁移现有 1.4G 数据；会话/笔记/知识库/索引四项比对一致；备份、索引重建、拖拽、导出功能在桌面版全部通过 | 0.5d |

合计约 **3 个工作日**（B2 Electron 可压到 1.5 天）。

## 7. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| Rust 工具链未安装（B1） | 无法直接开工 | 先装 rustup + MSVC Build Tools（~2GB）；或先走 B2 |
| `AppPaths` 定位错乱 | 打开是空库，像丢数据 | P0 先做数据目录可配，并在 `/api/health` 回显实际数据路径 |
| 端口冲突 | 启动失败 | 动态端口：从 39300 起探测，写入 `.port` 文件供壳读取 |
| WebView2 缺失（老系统） | 白屏 | 安装包内置 WebView2 Bootstrapper（Win10+ 一般已带） |
| 未签名 exe 被杀软误报 | 用户不敢装 | 自签名证书 + 提供 SHA256；正式分发再考虑代码签名 |
| SSE 长连接在壳内被挂起 | 回答卡住 | 窗口恢复时主动重连；后端已有半截入库兜底 |
| 双形态并存导致配置分叉 | 维护成本 | 数据目录、配置项、API 完全一致，只差「怎么启动」 |

## 8. 决策记录（2026-11-05 已确认）

| 决策点 | 选定 | 影响 |
|---|---|---|
| 壳技术 | **B1 Tauri 2** | 需先安装 Rust 工具链（rustup + MSVC Build Tools，约 2GB）；产物更小、内存更低 |
| 数据位置 | **程序目录 `data\.kb`** | 绿色便携形态，整包可拷走；**安装路径不能选 Program Files**（无写权限），建议 `D://应用//两翼知识库` 或桌面 |
| 附加能力 | **仅托盘常驻** | 关窗驻留托盘、后台任务继续跑；**不做**开机自启与自动更新（二期再议） |

### 由此带来的两处调整

1. **安装/放置目录**：安装包默认装到 `%LOCALAPPDATA%\Programs\两翼知识库`（用户可写），首次启动在其下创建 `data\.kb`；同时保留 `kb-home.txt`，允许把数据指到移动硬盘等位置。
2. **托盘语义**：点「×」= 隐藏到托盘（不退出）；托盘菜单提供「打开主界面 / 退出」；「退出」时才终止 sidecar 进程。
