# 定位差异分析 · 知识库 × 市面知识库产品

- 日期：2026-10-28
- 性质：定位分析（非功能规格）；若后续把差距转化为功能，另走设计流程
- 依据：本项目全部功能盘点 + 2026-10-28 对 MaxKB / Cherry Studio / AnythingLLM / Open WebUI / Msty 的调研

## 1. 我们的定位（一句话）

**个人本地知识库工作台**：语料零搬运（直指本地文件夹、自动增量索引）、以检索为中心（而非聊天为中心）、同时是给 AI 工具供数的服务端（MCP）。单机、无账号、全 Java 单进程、零使用成本。

## 2. 市场坐标

市面产品沿"心智"与"部署形态"两轴分布，我们站在目前无占位者的交叉点：**本地单机 × 知识库心智 × MCP 供数**。

```
        聊天客户端心智              知识库/平台心智
  ┌────────────────────────┬────────────────────────┐
  │ Cherry Studio（聚合50+模型）│ MaxKB / FastGPT / Dify   │
  │ Open WebUI / Msty        │ RAGFlow（深度文档理解）    │
  │        ↑ 服务器多人 · 容器部署 · 面向企业 IT          │
  ├────────────────────────┼────────────────────────┤
  │ AnythingLLM desktop      │ ← 我们在这里              │
  │ Obsidian + Copilot       │   本地单机 × 知识库心智     │
  │        ↑ 个人 · 文件在本地 │   × MCP 供数              │
  └────────────────────────┴────────────────────────┘
```

## 3. 逐产品差异

| 产品 | 心智 | 与我们相同 | 我们独有 | 它有而我们没有 |
|---|---|---|---|---|
| Cherry Studio | 通用 AI 聊天工作台 | 多厂商切换、知识库问答 | 知识库是它的附属功能；它需手动上传文件建库，我们指向文件夹自动增量索引；它只做 MCP 客户端，我们做 MCP 服务端 | 助手生态、绘图翻译、多模态 |
| Msty | 本地模型前端 | 混合检索、检索参数可调（我们以检索测试页部分覆盖） | 全自研零费用（它商用 $149/年）；接厂商 API 免本地 GPU | Ollama 本地模型、EPUB/YT 字幕入库、知识栈细粒度调参 UI |
| AnythingLLM | 文档 RAG + 引用 | 块级引用溯源 | 语料零搬运 | Agent flows、会议转录、移动端、团队空间 |
| MaxKB / FastGPT / Dify | 企业智能体平台 | RAG 基本盘 | 10 分钟上手、零运维、单机隐私 | 工作流画布、多租户、嵌入第三方系统（永不对标） |
| RAGFlow | 深度文档理解 | — | 轻量 | 扫描件 OCR、复杂版面/表格结构还原 |
| Obsidian + AI 插件 | 笔记管理 | 本地文件为主 | "文档消费"而非"笔记生产" | 双向链接、知识图谱 |

## 4. 我们独有、市面无组合的三件事

1. **语料零搬运**：市面产品几乎都要求把文档上传/导入它的库；我们直接指向本地文件夹，扫描与增量同步全自动。对已有大量文档资产的人是决定性差异
2. **MCP 供数端**：市面产品是"消费 LLM 的客户端"；我们把知识库作为检索工具供给 Claude Code 等编码 Agent——"写代码时顺手查公司文档"场景无现成竞品
3. **引用闭环**：块级引用 → 点击 → 预览抽屉定位命中块 → 一键原生应用打开原文，单应用内全链路

## 5. 定位边界（明确不做，且不构成劣势）

多用户/鉴权、工作流编排、移动端、模型聚合市场、云端协作。做了会把产品推向企业平台，丢掉"十分钟上手、零运维"的个人定位。

## 6. 主要差距（未来可选方向，未承诺）

1. 本地模型支持（Ollama，离线可用）
2. 扫描件 OCR、复杂 PDF 版面还原（对齐 RAGFlow 的招牌能力）
3. EPUB / 网页剪藏等更多入库格式
4. 知识栈细粒度调参 UI（检索测试页已部分覆盖）

## 7. 结论

我们不是"又一个 ChatGPT 客户端"，而是**本地文档资产与 AI 工具之间的检索层**。最近的邻居是 Msty 的 Knowledge Stack 与 AnythingLLM，但"文件夹直连 + MCP 供数"的组合市面无现成品。
