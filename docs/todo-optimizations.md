### ☐ 1. 大表向量化 400（语义检索缺失）

**现状**：`上线全流程知识库/工作量/三季度、二季度工作量-二部.xlsx` 已能进关键词索引（`c8116b0` 修好了抽取阶段的 StackOverflow），但批量向量化被 ark 拒绝：
`400 Bad Request from POST .../api/plan/v3/embeddings`，随后逐条重试仍失败 → 这两份文件只有关键词召回，没有向量召回。

**目标**：全部 210 个文件都能进向量索引；个别失败只影响该块，不拖垮整表。

**实现要点**
- `llm/OpenAiCompatEmbedding.java`：`embedAll` 增加
  - 单条文本超长截断（如 > 6000 字符截断，记录 warn）
  - 空/纯空白文本直接返回零向量或跳过（不发请求）
  - 批量失败时**二分拆批重试**（16 → 8 → 4 → 1），而不是整批丢
  - 记录失败批的首条文本前 200 字，便于定位是内容问题还是接口问题
- `ingest/IndexBuilder.java`：向量失败时把 `vectorFailed` 写进构建摘要，前端可见

**验收**
- 重建两翼库：`批量向量化失败` 日志为 0；`failedCount=0`
- 随机抽 3 个此前失败表的片段，做一次纯语义检索（无关键词命中）能召回

### ☐ 2. 生成中刷新页面丢回答（后端化）

**现状**：`POST /api/ask` 是同步 SSE，流绑定在浏览器连接上。刷新/切页面 = 连接断，回答只留半截入库，不会继续生成。

**目标**：刷新回来能接着看，生成过程不依赖页面存活。

**实现要点**
- 服务端：提问时创建「生成任务」（`ChatStore` 已有 `ACTIVE_ASKS` 标记，扩展成任务表：`taskId/sessionId/状态/已生成内容/开始时间`），由独立线程跑 `ChatService` 流式生成，边生成边增量落库
- 新增 `GET /api/ask/{taskId}/stream`（或 `/api/sessions/{sid}/stream`）：客户端连上后**先补发已生成部分**（replay），再接实时增量
- 前端 `views/AskView.vue`：进入会话时若该会话有运行中任务，自动连 replay 流；断线 3 次内自动重连
- 页面关闭不影响任务；任务结束写最终消息 + usage

**验收**
- 提问中途按 F5 → 重进会话能看到已生成内容并继续追加，最终回答完整
- 关掉标签页 30 秒后再打开 → 回答已完成，内容完整

---

### ☐ 3. 多会话并行生成

**现状**：一次只能有一个回答在生成（`ACTIVE_ASKS` 只是状态标记，实际生成是请求级串行体验），长回答时切到别的会话提问要等。

**目标**：不同会话可同时生成；同一会话内仍串行（避免同会话消息错序）。

**实现要点**
- 依赖第 2 项的任务化：任务按 `sessionId` 排队，不同 `sessionId` 并行（线程池 + 每会话队列）
- `chat/ChatStore.java`：`generating` 改为「本会话是否有运行中任务」
- 前端：侧栏会话项已支持「生成中」标记（`.kdot` / `genSid`），扩展为多会话同时标记；顶部输入框不再全局禁用，仅禁用当前会话

**验收**
- 会话 A 生成中，切到会话 B 提问 → B 立刻开始生成；A 的标记仍在转，切回 A 内容在继续
- 同一会话连续点两次发送 → 第二次排队或提示，不出现消息错序

## P1 — 日常收益明显

### ☐ 4. 笔记搜索（标题 + 正文）

**现状**：会话列表有搜索框（`AskView` 的 `sessQ`），笔记侧栏**没有搜索**；笔记多了只能靠文件夹翻。

**实现要点**
- 前端 `views/NotesView.vue`：侧栏加搜索框（参考 `.sessq` 样式），输入即过滤 `noteGroups`（标题匹配 + 若输入 ≥2 字则请求后端正文匹配）
- 后端 `notes/NotesController.java`：新增 `GET /api/notes/search?q=`，扫标题 + 正文返回 `id/title/folder/snippet`
- 搜索态下分组自动展开，命中片段高亮

**验收**
- 搜「上线」能同时命中标题含「上线」和正文含「上线」的笔记，命中处显示上下文片段

### ☐ 5. 笔记历史版本恢复界面

**现状**：后端每次非空保存都会在 `.kb/notes-history/{id}/` 留一份（每篇保留 20 份，另有 `.nonempty` 快照），**但没有任何界面入口**——数据在，用户看不到。

**实现要点**
- 后端：`GET /api/notes/{id}/history`（返回时间戳列表 + 大小）、`GET /api/notes/{id}/history/{stamp}`（取内容）、`POST /api/notes/{id}/restore?stamp=`（恢复，恢复前先备份当前版本）
- 前端：编辑器顶部加「历史」按钮 → 抽屉：左侧版本列表（时间 + 大小），右侧内容预览，底部「恢复此版本」（二次确认）

**验收**
- 改坏一篇笔记 → 打开历史 → 选上一版 → 恢复 → 正文回到旧内容，且当前版本也进了历史

### ☐ 6. 全局搜索（Ctrl+K）

**现状**：知识库（`SearchController /api/search`）、笔记（无搜索）、会话（前端过滤）各自为政。

**实现要点**
- 后端：`GET /api/global/search?q=` 并行查「各 KB 索引 + 笔记正文 + 会话标题」，统一返回 `type/kbId/docPath/title/snippet/seq`
- 前端：`App.vue` 挂全局命令面板（Ctrl+K），分组展示：文档 / 笔记 / 会话，回车跳转（文档→预览抽屉，笔记→笔记页打开，会话→问答页切会话）

**验收**
- Ctrl+K 输入关键词，三组结果都有；点文档直接开预览，点笔记直接打开该篇

### ☐ 7. 检索范围多选

**实现要点**
